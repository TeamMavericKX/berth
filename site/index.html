One daemon.
Two superpowers.

portless gave dev servers stable https://name.localhost URLs and demanded your sudo, your Node 24, and a root CA. portmap gave agents an honest dashboard and refused to touch TLS at all. berth is both halves, minus the taxes. 

$ berth run -- npm run dev
berth: myapi.localhost -> 127.0.0.1:4312 (pid 48221)

# frameworks that ignore PORT get real flags, not vibes
$ berth run -- vite dev
berth: viteapp.localhost -> 127.0.0.1:4377 (pid 48330)

# worktrees never collide — feature/auth prefixes itself
$ cd ../repo-auth && berth run -- npm run dev
berth: auth-myapi.localhost -> 127.0.0.1:4410 (pid 48502)

# share it over your tailnet — or the world
$ berth run --funnel -- python -m http.server

The whole job, in one listener

berth peeks the first byte of each connection — the same trick portless uses — and routes TLS to the certificate layer while plaintext flows to the HTTP router. Named URLs land on high ports, so there is nothing to elevate, and /etc/hosts gets one managed block that cleans up after itself.

◈

Named HTTPS, honestly

A local CA minted by the openssl binary you already have — never linked crypto for certificates — signs per-host leaves cached in ~/.berth/certs. Unknown hostnames fall back instead of failing. One port serves both schemes by peeking a single byte.

◇

An agent-first dashboard

portmap's best idea, kept: send Accept: text/markdown for the full status page plus API reference as markdown. Humans get a live glass console; LLMs self-discover everything.

⏻

Kill with a receipt

SIGTERM every listener on a port, poll zombie-aware for two seconds, SIGKILL only survivors, then tell you which happened. No lsof dependency, no orphans.

▦

Containers speak up

Docker and Podman sockets polled over plain HTTP-on-a-unix-socket; published ports surface as candidates tagged origin=container.

⛨

Mutations wear seatbelts

Kill and edit check Origin against localhost and honor a bearer token. portmap shipped permissive CORS on a kill endpoint; berth closes that door from day one.

⑂

Worktrees just work

Linked git worktrees prefix names with the branch tail — feature/auth becomes auth-myapp — while your root checkout stays exactly as named, even on feature branches. Parallel agent sessions never collide.

⟶

Tunnels are one flag away

--tailscale exposes the route to your tailnet, --funnel to the world. The ts.net authority attaches to the route row and shows up in the dashboard and /api/ports. Tailscale asleep? One clear line, app keeps serving locally.

Install & first run

Prebuilt static binaries for five platforms ship with every release. The five-minute human guide lives in docs/guide.md; the agent contract is docs/agents.md.

Download v0.2.0 — linux · macOS · windows source on github 
# build once — no runtime, no npm install, no node_modules
$ git clone https://github.com/TeamMavericKX/berth && cd berth
$ zig build -Doptimize=ReleaseSafe

$ berth run -- npm run dev     # URL printed; ctrl-c cleans up
$ berth trust                  # https URLs browsers believe
$ berth service install        # survives reboots, still no sudo
$ berth clean --yes            # leave with zero residue

Receipts or it didn't happen

The claims above are audited, not asserted. Source-of-truth documents, each with file:line citations:

  • docs/research/portless-dossier.md — ~25,100 lines TS, 42 files; the byte-peek demux (proxy.ts:690-706), framework injection table (cli-utils.ts:1095-1140), cert-by-spawned-openssl (certs.ts:231).
  • docs/research/portmap-dossier.md — ~4,344 lines Rust; markdown self-description (lib.rs:597+), the kill ladder (process.rs:66-125), the permissive-CORS flaw this project refuses to inherit (lib.rs:79).
  • docs/research/zig-feasibility.md — module-by-module feasibility verified against installed Zig 0.16, including why std has no TLS server and what that forced.
  • docs/adr/ — decisions with fallback plans: h1-first (ADR-0001), SQLite amalgamation (0002), linked OpenSSL + spawned openssl CLI (0003), scan-on-demand only (0004).
